# Gemma 4 31B MTP Timing Test - 2026-05-05

## Technique and Fairness Controls

- Models tested: `gemma4:31b-mlx-bf16` and `gemma4:31b-coding-mtp-bf16`.
- Ollama version: `0.23.1-rc0`.
- Before live model runs, the CLI was rebuilt and tested with `npm run build` and `npm test`; both passed.
- Each independent single-prompt test used the built CLI:
  `node packages/cli/dist/index.js --provider ollama --model <model> --think on --json-stream --max-turns 32 --prompt "<prompt>"`.
- Context setting: the CLI default context budget was used; no explicit `--context-tokens` flag was passed because the default is `262144`. Both tested Ollama model tags report `context length 262144` through `ollama show`. The CLI's Ollama provider uses the OpenAI-compatible endpoint and does not send a separate `num_ctx` override; a follow-up sanity check with the same endpoint showed `ollama ps` loading `gemma4:31b-coding-mtp-bf16` with `CONTEXT 262144`.
- Before each independent single-prompt test, all loaded Ollama models were stopped and Ollama was restarted:
  `ollama stop <loaded-model>`, `osascript -e 'quit app "Ollama"'`, wait for `ollama serve` to exit, then `open -a Ollama`.
- Timings are CLI run durations from the run log. They include cold model load after the Ollama restart, model reasoning/output, tool calls, validation commands, and final response. They exclude the pre-run Ollama restart setup time.
- For the conversation bonus, Ollama was restarted once per model sequence. Step 1 started a fresh session, and Steps 2-4 used `--resume <session-id>` so the model stayed in one continued conversation. Per-step timing and total wall clock were recorded.
- Prompts were kept identical between models except for model-specific target folder names, so generated files did not collide.
- The loose solar prompt is less fair because the two models chose different feature scope. A stricter solar prompt was added as a bonus run to make the outputs closer in size and feature set.
- The ping test used `ping -q -c 500 google.com` with default interval and `--shell-idle-timeout-ms 700000`. This test is dominated by the fixed external network command, so it is not a clean model speed test.
- Local 31B behavior matched the user's warning: several responses took multiple minutes.
- End-to-end agent work to run the tests, validate results, and produce this analysis took about 1 hour 25 minutes.
- After all tests, loaded Ollama models were stopped.

## Notes and Anomalies

- Conversation anomaly: the first conversation prompt asked for a CommonJS `sysinfo.js` file inside this repo, whose root `package.json` uses ESM semantics. That made `node test-projects/.../sysinfo.js` fail with `require is not defined`. Since this was not a recovery test, that attempt was stopped at 337 seconds and logged as an anomaly. The corrected conversation test used `sysinfo.cjs` for both models.
- The aborted anomaly target was `test-projects/mtp-conversation-31b-mlx-bf16-run01/sysinfo.js`; it is not included in the timing comparison.

## Bonus - Conversation Test

Target folders:

- `gemma4:31b-mlx-bf16`: `test-projects/mtp-conversation-fixed-31b-mlx-bf16-run01`
- `gemma4:31b-coding-mtp-bf16`: `test-projects/mtp-conversation-fixed-31b-coding-mtp-bf16-run01`

Prompt template used for Step 1, with `<target>` replaced by the target folder above:

```text
Create exactly one file at <target>/sysinfo.cjs. Use CommonJS and only Node built-ins os and process. Export a function named collectSystemInfo(options = {}) that returns an object with exactly these keys: hostname, platform, arch, cpuCount, totalMemoryMb, freeMemoryMb, uptimeSeconds, nodeVersion. When the file is run directly, print JSON.stringify(collectSystemInfo(), null, 2). Do not create any other files. After writing it, run node <target>/sysinfo.cjs and node -e "const { collectSystemInfo } = require('./<target>/sysinfo.cjs'); const info = collectSystemInfo(); console.log(info.cpuCount > 0 && !!info.nodeVersion);" and then finish.
```

Step 2:

```text
Modify only <target>/sysinfo.cjs. Add support for options.includeEnv with default false. When includeEnv is true, add an env object with only the present USER, SHELL, and HOME environment variables. The default collectSystemInfo() result must keep exactly the original eight keys and must not include env. Add a CLI flag --include-env that prints JSON with env included. Do not create, rename, or delete files. After editing, run node <target>/sysinfo.cjs, node <target>/sysinfo.cjs --include-env, and node -e "const { collectSystemInfo } = require('./<target>/sysinfo.cjs'); const base = collectSystemInfo(); const env = collectSystemInfo({ includeEnv: true }); console.log(!('env' in base) && env.env && typeof env.env === 'object');" and then finish.
```

Step 3:

```text
Modify only <target>/sysinfo.cjs. Add support for options.format with default value "json". If options.format is "summary", collectSystemInfo returns a single string exactly in this shape: hostname=<hostname> platform=<platform> arch=<arch> cpus=<cpuCount> memoryMb=<totalMemoryMb>. Add a CLI flag --summary that prints the summary string. Keep default JSON and --include-env behavior unchanged. Do not create, rename, or delete files. After editing, run node <target>/sysinfo.cjs --summary and node -e "const { collectSystemInfo } = require('./<target>/sysinfo.cjs'); const summary = collectSystemInfo({ format: 'summary' }); console.log(typeof summary === 'string' && summary.includes('hostname=') && summary.includes('cpus='));" and then finish.
```

Step 4:

```text
Create exactly two new files in <target>: data.json and index.html. Generate data.json from sysinfo.cjs by running node <target>/sysinfo.cjs > <target>/data.json after any edits needed. Build index.html as a dependency-free page that fetches ./data.json and renders a table with exactly these rows in this order: hostname, platform, arch, cpuCount, totalMemoryMb, nodeVersion. It must include the text "Data source: data.json generated by sysinfo.cjs". Do not create any other files. Do not modify sysinfo.cjs unless it is required to generate data.json. After writing, run node -e "JSON.parse(require('fs').readFileSync('<target>/data.json','utf8')); console.log('data ok');" and rg -n "data.json|hostname|cpuCount|nodeVersion" <target>/index.html and then finish.
```
